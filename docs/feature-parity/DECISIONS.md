# Decisiones — registro de decisiones del proyecto

Este documento registra (1) las decisiones bloqueantes de [PLAN.md](PLAN.md) §9.1 con el **default adoptado** y (2) las decisiones de implementación que se toman durante las fases. Lo mantiene el orquestador: cada fase reporta sus decisiones y se agregan a la segunda tabla.

## Decisiones bloqueantes (PLAN §9.1)

**Estado:** el usuario decidió D1 (Next.js en Vercel, 2026-10-29) y, con ello, el destino de despliegue de D8; las demás adoptan el default propuesto. Si una respuesta posterior lo cambia, se anota aquí qué fases se rehacen. La Fase 8 (integraciones reales) sigue **bloqueada** hasta que D4, D7 y D8 se confirmen con datos reales (credenciales de pago, precios, dominio y políticas).

| ID | Tema | Default adoptado | Motivo |
|---|---|---|---|
| D1 | Stack | Next.js (App Router) + TypeScript, desplegado en Vercel — decisión del usuario | El hosting es Vercel y Next.js es su preset nativo (rutas de servidor como `/api/leads` para la Fase 8, sin configuración extra). Sustituye al default original (Vite + React SPA); el resto del plan se mantiene con los equivalentes de Next (`src/app`, `next/navigation`, `process.env` / `NEXT_PUBLIC_*`). |
| D2 | Identidad de Bloom | Tokens de PLAN §4.1 con nombres de marca neutros; logo placeholder marcado `TODO(content)` | Permite paridad visual sin copiar la identidad de la referencia; la marca real se cambia en los tokens y en un solo componente. |
| D3 | Claims, credenciales y testimonios | No se renderizan; contenido propio genérico u ocultar el bloque, siempre detrás de flags apagados | No hay evidencia verificable de cifras, prensa, universidades, revisor experto ni testimonios (guardrails 2 y 3). |
| D4 | Pagos, precios y moneda | `MockCheckoutProvider`; los precios de PLAN §5.10 sólo como datos de demo etiquetados | Sin proveedor, credenciales ni precios reales no se pueden cobrar; la interfaz de adaptador permite cambiar de proveedor sin tocar la UI. |
| D5 | Alineación del label de las opciones | Abajo-izquierda (paridad con la referencia), con un token CSS para cambiarla | Es lo observado en el video y es reversible sin tocar los componentes. |
| D6 | Idiomas | Inglés, con la estructura i18n lista (copy fuera de los componentes); español como segunda fase | El copy de referencia está en inglés; separarlo desde el inicio evita reescrituras al traducir. |
| D7 | Temporizador de descuento | Detrás del flag `paywall.countdown.enabled`, apagado por defecto | La urgencia sólo es válida si el descuento realmente vence (guardrail 6); encendido arranca en 15:00 y no se reinicia al recargar. |
| D8 | Despliegue, privacidad y consentimiento | Destino de despliegue: Vercel (preset Next.js, sin `vercel.json`). No se despliega nada desde aquí (sin credenciales ni dominio): el equipo importa el repositorio en Vercel (ver README, *Deploy on Vercel*). Páginas legales (Terms, Privacy, Subscription Policy) como placeholders | El hosting es Vercel (decisión del usuario, junto con D1); no hay dominio ni política definida y el checkout es mock; no se envían datos a terceros. |

## Decisiones de implementacion

| ID | Fase | Tema | Decision | Motivo |
|---|---|---|---|---|
| I-01 | Migración Next | Fuentes | `next/font/local` con los `woff2` latin de `@fontsource-variable/inter` y `source-serif-4` copiados a `src/assets/fonts` (más sus licencias OFL). Las variables `--font-inter` y `--font-source-serif` van en `<html>` y `tokens.css` las compone en `--font-sans` / `--font-serif` con `'Inter Fallback'` (métricas ajustadas, `global.css`) detrás; `adjustFontFallback: false`. | Cero peticiones a Google Fonts y build sin red; copiar los archivos evita depender de la estructura de `node_modules`. Los paquetes fontsource quedan como devDependency sólo para refrescar la copia. |
| I-02 | Migración Next | Ruta de la galería | Carpeta real `src/app/gallery` + rewrite `/__gallery/:path*` → `/gallery/:path*` en `next.config.ts`. | App Router trata las carpetas con prefijo `_` como privadas (no enrutables); el rewrite conserva la URL del plan (`/__gallery`). |
| I-03 | Migración Next | Interruptor de herramientas de QA | `isDevToolsEnabled()` en `src/lib/env.ts`: verdadero si `NODE_ENV !== 'production'`, o si `NEXT_PUBLIC_VERCEL_ENV === 'preview'` y `NEXT_PUBLIC_ENABLE_DEV_TOOLS === '1'`. Las páginas de la galería llaman `notFound()` cuando es falso (404 en producción, comprobado con `next start`); el enlace de la home también depende de él. | Permite revisar el layout en deployments *preview* de Vercel sin exponer nunca la galería ni el contenido demo en producción. Lecturas literales de `process.env.X` para que Next las inyecte. |
| I-04 | Migración Next | `distDir` y tsconfig | `distDir: process.env.NEXT_DIST_DIR \|\| '.next'`. Next se apunta a `tsconfig.next.json` (un `extends` de `tsconfig.json`) con `typescript.tsconfigPath`. | Next rechaza dos dev servers sobre el mismo `distDir`. Además reescribe el tsconfig que usa añadiendo `<distDir>/types/**` a `include`; un config con `extends` queda intacto, así que `tsconfig.json` no cambia según el `distDir` de cada ingeniero. |
| I-05 | Migración Next | Versiones | Next 16.4.3 (Turbopack), React 19.3, TypeScript `~6.0.3` (typescript-eslint 8.72 soporta `<6.1`; TypeScript 7 queda fuera hasta que el tooling lo soporte), `engines.node >=20.9.0` (mínimo de Next; Vitest 5 exige Node 22.12+ sólo para los tests). | Combinación verificada con `next build`, lint, typecheck, tests y e2e; Vercel ejecuta Node 20, 22 o 24. |
| I-06 | Migración Next | ESLint | ESLint `^9.39` con flat config: `eslint-config-next/core-web-vitals` + `/typescript` + `eslint-config-prettier`. No se usa ESLint 10. | `eslint-config-next` 16.4 trae `eslint-plugin-react`, `-import` y `-jsx-a11y`, cuyos peer ranges llegan hasta ESLint 9; npm marca 9.x como sin soporte, revisar al actualizar esos plugins. `next lint` ya no existe en Next 16. |
| I-07 | Migración Next | Límites cliente/servidor | `'use client'` en `Button`, `OptionCard`, `RadioGroup`, `RadioGroupContext`, `CheckboxRow`, `Modal`, `StepTransition` y las demos de la galería con hooks; los componentes puramente visuales y las constantes (`timing.ts`, `clampProgress.ts`) quedan sin directiva. | Hooks, contexto, efectos, portales y handlers sólo funcionan en cliente; mantener constantes fuera de los archivos cliente permite importarlas desde servidor. |
| I-08 | Migración Next | Vitest | `vitest.config.ts` (jsdom, alias `@`, setup) sin `@vitejs/plugin-react` ni `vite` como dependencia directa; helper `tests/unit/helpers/nextNavigation.ts` que mockea `next/navigation`. Los tests de rutas pasan a `tests/unit/pages/*` (renderizan la página y comprueban `notFound`) y `tests/unit/env.test.ts`. | El transform JSX de Vite 8 usa el `jsx: react-jsx` del tsconfig (verificado: la suite pasa sin el plugin). |
| I-09 | Migración Next | `typecheck` | `next typegen && tsc --noEmit`. | Genera `next-env.d.ts` y los tipos de rutas del `distDir` activo desde un checkout limpio (ambos están en `.gitignore`), sin depender de un build previo. |
| I-10 | Migración Next | Telemetría y `AGENTS.md` | El servidor del e2e corre con `NEXT_TELEMETRY_DISABLED=1` y el README recomienda desactivarla; no hay `vercel.json`, ni `output: 'export'`. `next dev` escribe un bloque gestionado en `AGENTS.md`; se conserva en el repositorio. | Ningún dato a terceros, tampoco desde el tooling; el árbol queda limpio al versionar `AGENTS.md`. |
| I-11 | Migración Next | Primer pintado | El fondo lila (`--bg-page-lilac`) se pinta con CSS global en `html` y `body`; el stylesheet es un `<link>` que bloquea el render, así que no hay parpadeo. Se descartó el CSS crítico en línea. | Sustituye al CSS crítico de `index.html`; cubierto por el test e2e con JavaScript desactivado. |
